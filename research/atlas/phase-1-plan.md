## 目标

第一阶段把本库建成一份**高权威来源库**，而不是继续把长尾套件收全。

做法是：按大渠道把该渠道里最知名、最有影响力、可核验的头部来源先核实入库，写完概览层（做什么、有什么内容、权威性与依据、可信度默认为待诊断）。已收录的条目全部保留，不删；接下来的扩搜改走「权威优先」，不再以扫完某个 awesome 列表为第一优先。

深度分析不是第一阶段的完成标准。来源库线在头部来源入库后，再按准则逐一深挖；视效等专项分析线可以同步从本库已有相关来源开始，不必等第一阶段收完。

## 什么叫「最权威」

一条来源要进入第一阶段的新收录，必须同时满足：

1. **有可核验的官方出处**：官方网站、官方文档或官方仓库，能打开、能引用，不靠转述或猜测。
2. **属于下面五类之一**，并达到该类的头部标准。

不够这条线的候选记入「未决 / 第二阶段队列」，不进正式清单充数。

### A. 模型大厂的官方设计 / 界面 / 生成式 UI 体系

必查（有官方设计指南、界面规范、Artifacts / Canvas / 生成式 UI 文档或组件时才入库，没有就不编）：

- OpenAI
- Anthropic
- Google / Gemini

同步核对其它已有公开官方设计或 UI 文档的模型厂商（如 Microsoft Copilot、Apple、Meta、xAI）。只收官方本体，不收第三方解读博客当官方来源。发现渠道记「官网 / 文档 / changelog」，出品方记「大厂官方」。

### B. 平台级、经典设计体系

必查：

- Apple Human Interface Guidelines
- Google Material Design
- Microsoft Fluent
- 鸿蒙 / HarmonyOS 设计体系

这些是平台级打法，按「设计系统 / 主题 / kits」为主类收录（若官方明确以动效或组件规范为主，再按内容改主类）。同等量级、且有完整官方体系的候补（例如 Ant Design 官方）可列入核实队列，但不替代上面四家必查。

### C. 该领域已被当作基础设施的官方或标准项目

只收官方本体，不收其衍生套件。已经在清单里的，第一阶段只补核、不重复建条，例如官方 shadcn/ui、Motion、Vercel AI Elements。

第一阶段应核、若尚未在清单则补入的候选方向（以打开官方出处后为准，不预写结论）：

- 样式与底层 primitives：如 Tailwind CSS、Radix / Base UI、React Aria 等官方项目
- 动效与三维基础设施：如 GSAP、Three.js、React Three Fiber 等官方项目

第三方在这些基础设施上做的 kit、模板、主题，除非本身已是该领域公认标准，否则放到第二阶段。

### D. X 上专门做这块的高影响力账号

第一阶段要收的是**稳定产出设计资产 / 动效 / 生成式 UI 的专业账号**，以及他们指向的、尚未入库的官方产品。不是再扫一轮合集帖里的长尾产品名。

账号本身可以记为「发现渠道 = X」的作者条目或备注，但其产品仍要落到可核验的官网或仓库才能入库。头部标准（需可核验，不靠印象）：

- 长期、专题性输出，而不是单条爆款；
- 公开身份清楚（官方账号、产品作者、或被多家官方/高权威合集重复引用）；
- 能指向稳定产品或可引用的方法/规范，而不是只有情绪贴。

### E. GitHub 等开源平台上的头部项目

第一阶段只收：官方组织仓库、该领域标准项目，或星标/引用已经明显处于头部、并且仍在维护的基础设施。不再把「awesome 列表里还有但星标一般的套件」作为本阶段主任务。`awesome-shadcn-ui` 的剩余条目改为第二阶段或作为发现线索，不作为完成本阶段的条件。

## 来源库线的任务拆分

1. **建库形态**：为本目录补齐 README 与交接文档（本稿）；待确认后初始化 Git 仓库，并创建私有 GitHub 远程，方便另一人和另一 AI 稳定取用。
2. **A. 模型大厂**：逐家打开官方设计 / 生成式 UI / 界面文档，核实后写入清单与打分表。
3. **B. 平台设计体系**：核 Apple、Google、Microsoft、鸿蒙四家官方设计体系并入库。
4. **C. 基础设施**：核官方本体是否已在清单，缺的补，已在的只补依据。
5. **D. X 专业账号**：整理已遇到的高影响力作者，并按头部标准再核一批专门账号及其产品。
6. **E. GitHub 头部**：按官方 / 标准项目 / 高影响力维护仓补核，不继续以 awesome 余量为先。
7. **更新交互清单**：每批核实结果写入 Markdown 后，再合并进 `index.html` 发给委托方审阅。

每条仍走同一套核实：官网或官方文档、出品方、做什么、内容勾选、按五星加权打分。没有出处的不入库。

## 完成标准

第一阶段完成，是指 A–E 的必查对象都已经「核实并入库」或「已打开官方渠道、确认没有可收的官方设计/UI 资产并记明原因」。不是清单条数到某个整数，也不是深度分析全部做完。
