打分规则

权威性是加权初评，不能代替委托方的可信度标注。星级和依据都要展示。准则最后对齐时间：2026-11-11（America/New_York）。

目标

做一份业界设计资产与设计资源的全景地图清单，作为后续设计输入的依据，并逐步沉淀成我们自己的资源库。

不是什么都收。先把「去哪里找、各是什么、值不值得进输入库」看清楚，再按规则筛选。权威性、它做的是什么、具体包含什么内容，是决定收不收的核心依据。

清单要同时满足四件事：足够全面、可抽样验证可信度、能围绕我们自己的问题做深度分析，以及据此建立有权威性的资源库与结论。

四步流程（分层，不混用）

01 收全来源

全网按渠道扩搜，做成可筛选的资源库。

发现太多时，权威性是第一道过滤。
02 抽样核可信度

概览层写清它做什么、内容是什么、权威性依据是什么，并把内容勾选列出。委托方对照后标注「可信 / 不可信 / 待定」。

所说与事实不符（例如写成有视效，实际没有）则可信度低。
03 深度分析

只围着北极星问题做，服务于我们自己要维护和组装的目标。状态标「待分析 / 已分析」。

概览写完仍是待分析；深挖并回答了适用的北极星问题，才改为已分析。
04 沉淀资源库与结论

从已核实来源归纳类型、做法和共性洞察（动效有哪些类型、组件 / blocks / 动效各自怎么做、底层是否共用同一套方案，以及 AGUI / AI 方向上最有启发的做法等），反哺资源库。

问题定义随证据更新，不先定结论再找例子。任何结论性表述都必须带依据，不编造。

前两步是概览层：渠道、分类、做什么、有什么、权威性、内容勾选、可信度。第三、四步是深挖层：技术栈、组装模型、约束与灵活度、相关资产、问题结论。没分析完的来源可以进清单，但不能假装已经有结论。

设计输入类别

一条来源可以同时打多个类，但必须标一个主类。筛选项按主类来，不再用「高 / blocks / 其他」这种粗分，也不用「其他」兜底。

主类取值（出现新的稳定类别时，先补进本表再使用）：

  • blocks（可拼装的区块、页面片段）
  • 动效（motion、微交互、3D、shader、过渡等；以动效为主、同时提供可拼装区块的，主类仍为动效，并可加标「动效 blocks」）
  • components（UI 组件库、单组件与变体）
  • flows（任务流、关键路径、多步骤交互）
  • 图标 / 插画（原子资产，含光标等）
  • 色板 / 字体
  • 模板 / 落地页
  • 交互 / 微交互（不完全等同于现成组件）
  • 背景 / 材质
  • 设计系统 / 主题 / kits
  • 生成式 / AI 搭建（提示词库、AI 建站或页面生成）
  • agent / 生成式 UI（Agent 界面、生成式 UI 协议或工具，不是视效图库）

内容勾选用「是 / 部分 / 无」记录，清单上可视化为勾、部分标记、叉。

渠道与出品方

每条来源记两个字段，不再用「起点 / 扩搜」当渠道。「起点」只表示最初由委托方提供的种子名单，属于发现渠道的一种取值，不是出品分类。

发现渠道

这条是从哪找到的，取值限定为：

  • 种子名单
  • X
  • GitHub
  • 官网 / 文档 / changelog
  • 设计社区（如 Dribbble、Mobbin、Layer）
  • 目录 / 榜单 / 合集
  • newsletter / 博客
  • Discord 等社区
  • 付费市场（如 ThemeForest、Lemon Squeezy）
  • registry / npm
  • Figma Community

发现新的高效渠道时先写入本表，再使用。一条来源若经多渠道重复出现，发现渠道记首次进入清单的渠道，其他渠道可记在备注。

出品方类型

谁做的，取值限定为：

  • 大厂官方（如 Vercel、Cal.com、Anthropic、OpenAI；须有官方出处，不臆测归属）
  • 开源主导项目（如 shadcn/ui、Motion）
  • 独立作者 / 工作室
  • 付费产品公司
  • 社区合集 / 目录

说不清就写「依据不足」，不编。大厂下属或收购关系（如 Kibo UI 被 Shadcnblocks 收购、Origin UI 迁到 Cal.com 的 coss.com/ui）在依据里写明，出品方按当前官方归属归类。

每条资源要查清的维度

概览层（必查）

  • 发现渠道与出品方类型（见上）。
  • 做什么 / 服务谁：解决的问题、面向谁、在输入链路上扮演什么角色（灵感、可复制代码、设计稿、完整套件等）。
  • 具体包含什么内容：主类、兼有类，以及「是 / 部分 / 无」勾选；深度与完整度如何。
  • 权威性：按下方准则打分，星级和依据都展示，不单写一个形容词。

概览层一并记录（筛选用）

  • 覆盖范围：只做一类，还是多类覆盖。
  • 形态：开源库、展示站、可复制代码、Figma/设计稿、付费套件、登记处、生成/搭建工具等。
  • 更新频率与维护状态：是否仍在维护，最近一次更新大约何时。
  • 许可：能否商用、修改、再分发。
  • 获取成本：免费、开源、订阅、一次性买断，以及有哪些关键能力要付费。未打开定价页的标「未核实」，不编造价格。
  • 可操作性：能否直接当作设计/开发资产用，还是只能当灵感参考。

深挖层（分析状态改为「已分析」前必须查清）

  • 相关主题与可连带的资产，以及一起用时的边界。
  • 技术栈与实现方案：框架、样式方案、动效库；是否仍走 shadcn / registry / CLI，或其他路线。
  • 组装模型：复制源码、registry、主题令牌、槽位/变体、AI 生成等。
  • 约束与灵活度：单元怎么拆、限制在哪、灵活改动靠什么实现。
  • 是否适合作为可自由组装的输入。
  • 开放式洞察：最先进或最有启发的一点，尤其是 AGUI / AI 相关；无则标明尚未形成洞察。必须附依据（截图、原文或可核验页面），不编造。

未做深挖的来源，这些字段留空，分析状态保持「待分析」。

权威性打分

满分 5 星。先按五项加权得到 0–5 的总分（保留一位小数），再换成星级。星级和打分依据都要展示。星级是辅助判断，不能代替委托方的可信度标注。

不得编造 GitHub 星标、推送时间、引用或价格；以官网与 gh api 等当场可核验的事实为准。无公开稳定主仓时，在依据中注明「无稳定主仓」，该项相关分数按低档计。

权重与分项（每项 0–5）

分项权重计分口径
出品方30%大厂官方或该领域公认的标准项目接近满分；独立但官网与主仓都清楚的中高；出处清楚但主仓很弱、已停滞，或几乎只靠营销站的往下打。说不清写「依据不足」。
维护与规模25%以已核实的 GitHub 星标与最近推送为准。无公开稳定主仓时注明「无稳定主仓」，按低档计。
被引用20%被官方文档互链或作为行业默认入口被持续引用最高；高质量合集次之；证据不足时取保守分，并注明「引用证据有限」。
文档与可核验15%官网、文档、示例、许可、定价能否当场核对。
许可与获取清晰度10%许可证和获取方式（免费/付费边界）都清楚加分；有一项清楚、另一项未核实或含混为中档；都说不清为低档。

1. 出品方（30%）

5大厂官方，或该领域公认的标准项目（如官方 shadcn/ui、Motion 官方）。
4独立但在生态中被广泛使用，官网与主仓都清楚。
3独立作者/工作室或付费产品公司，官网与出处清楚。
2出处清楚但主仓很弱、已停滞，或几乎只靠营销站。
1出处含混，几乎无法核验是谁在维护。
0完全无法判断（依据写「依据不足」）。

官网仍活跃但仓已停更（或权威已迁走）时，按当前官方主仓计，并在依据里写明迁移或停更事实。

3. 被引用（20%）

5被官方文档互链，或作为行业默认入口被持续引用。
4稳定出现在高质量合集（如高星 awesome 列表）或同类讨论中反复出现。
3有合集或渠道提及，但还不算默认入口。
2主要来自种子名单或少量提及。
1几乎看不到独立引用。

证据不足时取保守分，并注明「引用证据有限」。

4. 文档与可核验（15%）

5官网、文档、示例、许可、定价都能当场核对。
4官网与文档/示例清楚，个别项（如精确价格）尚未打开。
3有可打开的官网和基本说明，细节不全。
2以客户端渲染为主、缺少稳定文档或主仓，核验困难。
1主页无法打开，或关键信息对不上。

5. 许可与获取清晰度（10%）

5许可证和获取方式（免费/付费边界）都清楚。
3许可或定价有一项清楚、另一项未核实或含混。
1许可与获取方式都说不清。

星级换算

4.5–5.0 五星 3.5–4.4 四星 2.5–3.4 三星 1.5–2.4 两星 0–1.4 一星

清单上同时展示星级、总分，以及一句依据（含关键星标、维护情况或「无稳定主仓」等）。例如公开仓只有约 150 星的来源，即使官网完整，维护与规模、被引用也会把总分拉下来。

打分可随新的可核验证据修订，修订时保留依据，不因观感改分。

两层状态

  • 可信度：待诊断 / 可信 / 不可信 / 待定。这是委托方抽样后的判断，助手只代为写入清单，不替其下结论。
  • 分析状态：待分析 / 已分析。概览写完仍是待分析；深挖并回答了适用的北极星问题，才改为已分析。

证据与不编造

结论、打分、洞察和「最先进」这类判断，都必须能指回当场可核验的依据，逻辑要严谨。依据优先用：官网或文档的原文与截图、公开仓库（含 gh api 核实的星标与推送时间）、可打开的示例或源码、定价/许可页面。没有截图或原文支撑时，不得把推测写成结论，也不得补全没看到的技术细节、价格、归属或洞察。

看过仍证据不足的，写「尚未形成结论」或「尚未形成洞察」；引用证据有限时在依据里注明。截图与引用材料保存在调研记录中，和结论一起可回溯。

使用方式

  1. 先用本准则框定类别、渠道、维度与打分方法，再扩搜或改清单。
  2. 新来源先写完概览层（含打分依据），可信度为「待诊断」，分析状态为「待分析」，再进入清单。
  3. 委托方抽样标注可信度后，再安排深挖；深挖围绕北极星问题，不把概览写成分析完成。
  4. 依据权威性、内容类型、可信度与可操作性决定是否进入输入库；不满足的可留在「已发现、暂不收录」，以免重复劳动。
  5. 类别、渠道、维度、打分规则如有增补，先改本准则，再继续扩搜或改清单。
  6. 不编造网址、星标、价格、归属、技术细节、洞察或任何结论。结论须附可回溯依据（截图、原文、公开仓或可核验页面）。
